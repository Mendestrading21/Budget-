# Skills Budget — ordre d’autorité

| Skill | Statut | Usage |
|---|---|---|
| `budget-prisme` | **Actif et obligatoire** | Toute modification substantielle de Budget |
| `apple-design` | Auxiliaire | Références Apple et accessibilité, sans remplacer Prisme |
| `budget-neon-ultra` | Historique | Consultation seulement; ne pas exécuter sa roadmap |

## Règle

`CLAUDE.md` puis `budget-prisme/SKILL.md` et ses références font foi.
Aucun agent ne combine plusieurs roadmaps ou ne réactive un programme
historique pour « améliorer » le dépôt.

Un élément utile d’un skill historique peut être repris uniquement si :

1. il ne contredit aucun invariant actuel;
2. il répond au lot en cours;
3. il est porté dans le skill actif ou la documentation autoritative;
4. il reçoit les tests et preuves actuels.

Les nouveaux skills doivent avoir un périmètre distinct, un propriétaire
et une règle de priorité documentée ici. Un nouveau nom de programme ne
doit jamais servir à contourner la checklist Budget 1.0.
